# 日常操作与后台核对优化

2026-10-16。

- 健康的 Windows 目录监控以文件事件为主，保持复制完成后的静默等待；全库兜底从 30 秒改为 60 秒。监控降级时仍每 3 秒检查目录指纹，15 秒兜底扫描。每 3 秒的根目录可用性和监控注册检查保留。后台扫描通过非阻塞锁让出正在执行的用户操作。
- 界面读取带版本的最近一次核对结果，未变化时只返回小型确认结果。前端合并重复刷新，最小化时不进行界面轮询。文件启停、改名等写操作仍执行原有现场检查和失败回滚，不能以界面缓存授权写入。
- 打开目录只读取配置和检查该目录，不扫描 MOD，也不触发后续刷新或锁定界面。
- 当前目录手动刷新按游戏和目录双重限定，只更新该范围。设置中的“刷新全部”继续扫描全部目录。
- 备注和封面保存返回单个 MOD 的核对结果，调用界面直接合并更新，不重复拉取全库。裁切图片本身不会通知游戏库变化。普通完整快照接口保留，便于显式核对和诊断。
- 搜索索引和侧栏统计按数据变化缓存；搜索结果延后渲染以优先响应输入；列表项复用，封面按需加载和异步解码。保持原有可变行高和滚动方式。
- 未变化的管理信息不重复写入 SQLite；轻量读取不再复制整个管理库用于回滚。

## 验证

Rust 测试覆盖目录刷新不越界、缓存读取不访问 MOD 状态、目标 MOD 局部核对、目录打开不核对全库，并保留启停冲突、链接保护和回滚回归。

`scripts/qa-library-performance.cjs` 使用独立目录中的 1,000 个真实文件和真实 Debug WebView，记录请求而不伪造后端响应。检查搜索、清空、滚动、详情打开、保存请求次数、当前目录刷新范围、其他目录实时变化、禁用文件夹新增文件状态、未变化版本响应、同名冲突，以及目录临时不可用的反馈。运行结果和本机搜索耗时记录在 `_local/output/library-performance-qa.json`；一次测量不能代表所有电脑、磁盘或 MOD 结构的耗时。

另运行手动备注/封面操作和启动主题回归。所有文件操作验证均在独立测试目录完成。

本次结果：核心测试 100 通过、0 失败、1 项性能探针默认忽略；真实 WebView 的 8 组性能/文件状态检查、7 组手动保存/封面检查和 6 组主题检查通过；前端生产构建与 Windows Release 构建通过。
