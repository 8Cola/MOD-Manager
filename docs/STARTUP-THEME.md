# 启动主题闪烁修复

2026-10-16：窗口不再先以固定浅色显示，再等待前端读取偏好。

- 创建窗口前，从已经加载的 SQLite 管理信息中读取主题；通过文档初始化脚本在 React 和样式加载前应用主题。
- 原生窗口／WebView 背景和页面背景保持一致；首屏设置与数据就绪后再显示窗口，不增加额外扫描。
- React 初始状态使用同一主题偏好，避免默认“跟随系统”覆盖手动深色或浅色。
- 首屏恢复滚动位置在布局阶段完成，减少显示后的跳动。
- 运行中切换主题、系统外观变化继续同步页面和窗口背景。
- 不依赖隐藏窗口的动画帧回调，避免 WebView 暂停帧回调导致窗口无法显示；界面长时间加载失败时通过原生错误提示退出，不留下隐形的锁定实例。

验证：前端生产构建通过；Rust 96 项回归通过，0 失败、1 个性能探针默认忽略。`scripts/qa-startup-theme.cjs` 在独立目录启动真实 Debug WebView，通过代理暂停主模块加载，确认窗口未提前显示，文档已有正确主题；然后释放模块并核对首屏主题记录。手动深色配浅色系统、手动浅色配深色系统、系统偏好的启动与实时变化均通过。

脚本需要 Playwright 和运行在 1421 端口的 Vite。它使用 1420 端口代理延迟加载，不修改真实游戏文件或本机系统主题。报告保存在 `_local/output/startup-theme-qa.json`。

## 切换外观的响应速度

外观按钮立即更新界面，后台串行保存最后一次选择，不再等待全库快照和文件核对，也不触发无关的目录刷新。后台快照不会覆盖尚未保存的主题选择；保存失败时提示并恢复已保存主题，关闭窗口前等待正在进行的保存。

新增紧凑设置响应及保存失败回退的核心测试，Rust 回归 97 项通过、0 失败、1 项性能探针忽略。真实 WebView 回归包含：暂停设置保存时界面仍立即变色、连续切换以最后一次选择为准、后台刷新不撤销待保存选择、保存失败恢复，以及原有的三组启动主题检查。
